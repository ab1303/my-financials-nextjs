#### 2. Fixed a real design issue in the rollback gate (mid-session)

The original `apply-patch.mjs` rollback gate rejected the patch if `overlapCount` (number of overlapping files) didn't strictly decrease. This was unsatisfiable for files claimed by ≥3 features — removing one owner leaves the file with 2 owners (still overlapping), so file-count stays unchanged. Batch-1 t001 hit this rollback on first run.

**Fix** (user-approved before applying):

- `lib/overlaps.mjs`: added `overlapParticipations()` — sum of `claimedBy.length` across overlapping files. Strictly decreases on every legitimate redundant-ownership removal.
- `apply-patch.mjs`: rollback gate switched from `overlapAfter >= overlapBefore` (files) to `partsAfter >= partsBefore` (participations). Audit row + log line now include both metrics.
- `report.mjs`: header now shows `overlap-files=N · overlap-parts=M`.
- `spec/harness/spec-remediation/lld.md`: Invariant #1 clarified to spell out participations vs file-count and explain the trade-off.

Re-ran batch-1 after the fix; all three patches applied cleanly with t003 correctly entering the idempotency no-op path.
