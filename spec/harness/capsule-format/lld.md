# Capsule Format — Low Level Design

> Read `context.md` first for motivation. This document specifies the
> file contracts, capsule template, parallel decomposition, and
> acceptance gates.

## Architecture

```
[ spec/index.json ]                      ← canonical manifest
[ spec/{domain}/{feature}/context.md ]   ← prose source
[ spec/{domain}/{feature}/capsule.yml ]  ← optional hand-overrides
              │
              ▼
[ scripts/harness/capsule-format/generate.mjs ]
   - reads manifest entry + context.md front-matter + optional yml
   - renders the fixed-section capsule template
   - measures token count; aborts feature if >800
   - writes spec/{domain}/{feature}/capsule.md
              │
              ▼
[ spec/{domain}/{feature}/capsule.md ]   ← derived artifact
              │
              ▼
[ scripts/harness/capsule-format/check.mjs ]
   - re-runs generation in --dry-run
   - asserts zero diff vs on-disk capsule
   - asserts every feature has a capsule
   - asserts every capsule ≤800 tokens
   - invoked from pnpm spec:check
```

**No LLM in the runtime loop.** The generator is pure string templating.

## File layout

```
spec/harness/capsule-format/
├── context.md
└── lld.md                              (this file)

scripts/harness/capsule-format/
├── generate.mjs                        # main entry: manifest → capsule.md
├── check.mjs                           # staleness + budget gate (wired into spec:check)
├── lib/
│   ├── template.mjs                    # renders the fixed-section template
│   ├── tokenize.mjs                    # tiktoken wrapper, single export
│   └── front-matter.mjs                # YAML front-matter parser
└── README.md                           # short pointer to this LLD

spec/{domain}/{feature}/
├── context.md                          (may grow optional YAML front-matter)
├── lld.md
├── capsule.yml                         (optional override; absent for most features)
└── capsule.md                          (generated; committed)
```

## Capsule template (fixed sections, in order)

Every `capsule.md` has exactly these sections in this order. Empty
sections render the literal string `_None._` rather than being
omitted — predictable structure beats compact output for cheap-model
parsing.

```markdown
# {feature.id} — Capsule

<!-- GENERATED by scripts/harness/capsule-format/generate.mjs
     SOURCE-SHA: {sha of context.md + manifest entry at generation time}
     TOKENS: {n}/800 -->

## Purpose
{1–3 sentences. Sourced from capsule.yml `purpose:` if present,
otherwise the first paragraph of context.md.}

## Owns
{Bulleted, by bucket. Buckets with zero entries are omitted entirely
to save tokens. File paths verbatim from manifest.}

- **routers** — `src/server/trpc/router/foo.ts`
- **services** — `src/server/services/foo.ts`
- **components** — `src/components/foo/*`

## Invariants
{Numbered list, verbatim from manifest invariants[]. If none, render
`_None declared._`}

1. Reimbursements must update both legs of the ledger atomically.
2. ...

## Consumed by
{Reverse index. Top 5 features that have this feature's owned files in
their consumes[]. If >5, append `…and N more — see spec/index.json`.}

- transactions.transaction-ledger
- shared.ui-primitives

## Gates
{Auto-derived: type-check + lint always; spec:check always; build only
if owns[].app or owns[].components non-empty; custom gates if listed
in capsule.yml `gates:`.}

- `pnpm run type-check`
- `pnpm run lint`
- `pnpm spec:check`

## Deeper context
- Context: [`spec/{domain}/{feature}/context.md`](./context.md)
- LLD: [`spec/{domain}/{feature}/lld.md`](./lld.md)
{If capsule.yml lists `references:`, append them here.}
```

### Token budget enforcement

- Measured via `lib/tokenize.mjs`, which wraps `@anthropic-ai/tokenizer`
  (Claude BPE — matches the dominant subagent model family in this
  repo). If the dependency is unavailable in CI, fall back to
  `tiktoken` with `cl100k_base` and apply a 1.1× safety multiplier
  (Claude tokens tend to be ~10% denser).
- Budget: **≤800 tokens** of the rendered file, comment header
  included.
- If a capsule exceeds budget, generation fails with exit code 4 and
  the offending feature id. The author must either trim invariants /
  shorten the purpose blurb (via `capsule.yml`), or split the feature.

### Optional `capsule.yml` override

```yaml
# spec/{domain}/{feature}/capsule.yml
purpose: |
  Two short sentences when the context.md opening paragraph is too
  long or too vague.
gates:
  - pnpm prisma validate
references:
  - docs/reimbursement-patterns.md
```

Override fields are **additive only**. The generator never lets
`capsule.yml` suppress invariants, owns, or consumed-by data — those
remain derived. This keeps the override surface narrow enough that a
cheap model can predict capsule contents from the manifest alone in
~95% of cases.

## Parallel streams

The implementation decomposes into **four independent streams**
dispatchable as parallel subagents.

### Stream A — Generator + template

**Subagent role:** Node script implementer.

**Owns (will create):**
- `scripts/harness/capsule-format/generate.mjs`
- `scripts/harness/capsule-format/lib/template.mjs`
- `scripts/harness/capsule-format/lib/front-matter.mjs`
- `scripts/harness/capsule-format/README.md`

**Tasks:**
1. Load `spec/index.json`.
2. For each feature: read its `context.md` (extract optional YAML
   front-matter via `front-matter.mjs`), read optional `capsule.yml`,
   compute the reverse `consumes[]` index from the manifest, render
   via `template.mjs`, measure tokens, write `capsule.md`.
3. Write a generation-summary line per feature to stdout
   (`✓ feature.id  412 tokens` / `✗ feature.id  847 tokens — OVER`).

**Exit codes:** 0 success; 4 any capsule over budget; 5 missing
required manifest field.

**Done when:** `node scripts/harness/capsule-format/generate.mjs`
emits 91 capsules, all ≤800 tokens, with median in 400–600.

### Stream B — Tokeniser wrapper

**Subagent role:** small-scope Node implementer.

**Owns (will create):**
- `scripts/harness/capsule-format/lib/tokenize.mjs`

**Tasks:** export `countTokens(text: string): number` with the
Claude-first / `tiktoken`-fallback policy described above. Pure
function, no I/O beyond loading the BPE table once.

**Done when:** unit-tested against a 100-line fixture; result within
±2% of the Anthropic web tokenizer for three sampled capsules.

### Stream C — Staleness check + `spec:check` integration

**Subagent role:** script editor.

**Owns (will create):**
- `scripts/harness/capsule-format/check.mjs`

**Owns (will modify, narrowly):**
- `scripts/harness/spec-manifest/spec-check.mjs` (add invocation of
  `check.mjs`; co-owned for this delta only)
- `package.json` `spec:check` script (no change if it already shells
  out to `spec-check.mjs`)

**Algorithm:**
1. Run the generator in `--dry-run` mode (template render to memory,
   no disk write).
2. Compare each in-memory capsule byte-for-byte to its on-disk
   counterpart. Any diff → stale.
3. Assert every manifest feature has a `capsule.md` on disk.
4. Assert every capsule ≤800 tokens.
5. Exit 0 if clean; exit 6 with the list of stale / missing /
   over-budget features otherwise.

**Done when:** `pnpm spec:check` fails on a deliberately-modified
capsule and passes after regeneration.

### Stream D — Feature registration & HLD update

**Subagent role:** spec librarian.

**Owns (will modify):**
- `spec/index.json` (add `harness.capsule-format` entry)
- `spec/harness/hld.md` (move from "Planned" to "Catalogue")

**Manifest entry:**


## Sequencing & parallelism

```
Phase 0 — Spec finalisation (this document approved)

Phase 1 — Parallel implementation (≤ 20 min wall-clock)
   ├─ Stream A: generator + template      ──┐
   ├─ Stream B: tokeniser wrapper           │ four subagents
   ├─ Stream C: staleness check             │ dispatched in parallel
   └─ Stream D: feature registration      ──┘

Phase 2 — Integration (sequential, ≈ 10 min)
   ├─ Run: node scripts/harness/capsule-format/generate.mjs
   ├─ Eyeball median token count + 5 random capsules for readability
   ├─ Run: pnpm spec:check          (expect pass with capsules clean)
   └─ Commit: 91 new capsule.md files + scripts + manifest update

Phase 3 — Downstream wiring (separate feature, not this one)
   └─ Update implement-from-spec / spec-remediation orchestrators to
      hydrate subagent prompts from capsule.md rather than lld.md.
```

**Wall-clock target: ≤ 35 minutes total.**

### Why these streams are independent

| Stream | Reads | Writes | Conflicts |
|---|---|---|---|
| A | manifest, context.md files | new script files | depends on B's tokenize.mjs interface only |
| B | nothing at design time | one new file | none — pure function |
| C | manifest, on-disk capsules | new script + small edit to spec-check.mjs | none — additive integration |
| D | manifest, harness/hld.md | same files | A's generator runs in Phase 2, after D's manifest entry exists |

**One contract constraint:** Stream A imports
`./lib/tokenize.mjs` with the signature `countTokens(text) => number`.
Stream B must ship that exact signature. Document it in both stream
prompts.

**One ordering constraint:** Phase 2 must run Stream D's manifest
update **before** the generator, so the new feature itself gets a
capsule on first run.

## Invariants (run on every CI / pre-push invocation)

1. **No hand-edited capsules.** `capsule.md` files include a header
   comment that `check.mjs` regenerates; any divergence fails the gate.
2. **Token budget is hard.** Generation aborts; CI never ships a capsule
   over 800 tokens.
3. **Idempotency.** Two consecutive `generate.mjs` runs produce zero
   diff.
4. **No LLM at runtime.** Generator and checker make zero network
   calls.
5. **Override surface is narrow.** `capsule.yml` may only add to
   purpose / gates / references — never suppress invariants, owns, or
   consumed-by.

## Implementation notes (2026-07-01)

### Deviations from spec

1. **Owns[] truncation in template.** `lib/template.mjs` caps each
   bucket at 5 entries + `…and N more` to keep large features
   (`transactions.transactions` had 30+ files) within the 800-token
   budget. The spec's "file paths verbatim from manifest" applies to
   the first 5; the truncation is a budget-enforcement mechanism, not
   a data omission — the full list is always in `spec/index.json`.

2. **Sub-feature fallback.** 7 features in the manifest have no
   `context.md` (sub-features with only `lld.md`). `generate.mjs`
   falls back to `lld.md` for these; purpose extraction still works.

### Open questions — resolved inline

1. **Tokenizer choice.** `@anthropic-ai/tokenizer` **exists on npm**
   and was installed as a devDependency. Native Claude BPE; no 1.1×
   multiplier needed.
2. **`capsule.yml` in `owns[]`.** Confirmed: owned by the feature it
   describes. Not a tracked `owns[]` entry (it's optional per-feature
   config, not a harness script).
3. **Small features get capsules.** Confirmed: all 95 features,
   including tiny ones, have a capsule. Minimum observed: 177 tokens.
4. **`harness.capsule-format` self-capsule.** ✅ Generated correctly
   on first run — `owns[].services`-only features handled with no
   special-casing.
